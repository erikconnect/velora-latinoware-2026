01 / O PROBLEMA WHY NOW?

A web mudou.

A nossa stack de motion nem sempre.

Por anos, transições e storytelling de interface significaram bibliotecas, observers, listeners e mais JavaScript no caminho crítico.

01

Mais runtime

Mais dependências, hidratação e pontos de falha para comportamentos que hoje o browser já executa.

02

Mais acoplamento

A animação fica presa ao framework ou à arquitetura do app, em vez de ser uma capacidade do documento.

03

Menos portabilidade

Trocar React, Tailwind, WordPress ou HTML puro não deveria exigir reescrever a linguagem de motion.

E se motion fosse parte da semântica do HTML e da capacidade nativa do CSS?

03 / HELLO, VELORA ATTRIBUTE GRAMMAR

Uma cena inteira cabe em poucos atributos.

O contrato acompanha o HTML.

Sem binding por framework. Sem API imperativa para descrever uma sequência simples. O CSS resolve timing, ranges e composição.

vl-scene
Define o relógio e o contexto da cena.
vl-stage
Mantém o palco estável enquanto a narrativa progride.
vl-act / vl-span
Organiza beats e sobreposição sem timeline JS.
scene.html
<section
  vl-scene
  vl-timeline="view"
  vl-pin="3"
  vl-scrub>

      Zero-JS motion

07 / CSS CONDICIONAL PROGRESSIVE ENHANCEMENT

Motion também pode responder ao contexto.

O modo muda.
O contrato permanece.

standardEquilíbrio entre tempo, distância e easing.
subtleRápido, curto, discreto.
cinematicMais profundidade, duração e presença.
stillMovimento reduzido por decisão autoral.

CSS if() é enhancement. O baseline precisa continuar correto sem ele.

motion-conditions.css
/* baseline */
[vl-motion="subtle"] {
  --vl-distance: .55;
  --vl-duration: .8;
}

/* progressive enhancement */
@supports
  (width: if(media(width > 1px):
    1px; else: 2px)) {

  [vl-motion] {
    --vl-blur: if(
      media(prefers-reduced-motion: reduce):
      0;
      else: 12px
    );
  }
}

11 / ACESSIBILIDADE THE EFFECT MAY DISAPPEAR

“Zero JS” não vale nada se a experiência quebrar.

O efeito pode desaparecer.
A interface não.

↘

Reduced motion

prefers-reduced-motion colapsa movimento de forma centralizada — não efeito por efeito.

{ }

Progressive enhancement

Recursos emergentes são guardados por @supports. O baseline continua utilizável.

</>

Semântica primeiro

A API vive sobre HTML real. Motion é camada de comportamento, não substituto para estrutura acessível.

14 / 19

12 / O QUE O VELORA NÃO É BOUNDARIES MATTER

Limites claros tornam o projeto mais útil.

Não é “mais um Tailwind”.
Não é “GSAP sem JS”.

01

Não é um framework obrigatório de UI

Importe só motion-core e mantenha seu próprio sistema visual.

02

Não é uma timeline universal

Casos altamente programáticos continuam pertencendo a ferramentas programáticas.

03

Não elimina JavaScript do produto

A proposta é zero runtime JS para a lógica de animação — não “sites sem JavaScript” como dogma.

O objetivo é diminuir a superfície de JavaScript onde o browser já tem primitivas melhores.
