03 / 17

O PROBLEMA WHY NOW?

A web mudou.

A nossa stack de motion nem sempre.

Por anos, transições e storytelling de interface significaram bibliotecas, observers, listeners e mais JavaScript no caminho crítico.

01

Mais runtime

Mais dependências, hidratação e pontos de falha para comportamentos que hoje o browser já executa.

02

Mais acoplamento

A animação fica presa ao framework ou à arquitetura do app, em vez de ser uma capacidade do documento.

03

Menos portabilidade

Trocar React, Tailwind, WordPress ou HTML puro não deveria exigir reescrever a linguagem de motion.

E se a intenção de motion fosse declarada no HTML e executada pela capacidade nativa do CSS?

Ato 02 / STORY INTENT → BROWSER

Cada passo é uma tela. O palco fica fixo enquanto o relógio compartilhado avança.

Seis passos da intenção ao navegador.

PASSO 1

Intenção

Diga como a página deve parecer. “Quero que este título suba ao entrar.”

PASSO 2

Primitiva

Escolha um movimento pequeno e nomeado. clip-rise

PASSO 3

Canal

Escolha quando acontece. <h2 vl-enter="clip-rise">

PASSO 4

Parâmetro

Ajuste com uma propriedade personalizada. --vl-blur-from: 12px

PASSO 5

Cena

Organize o tempo entre elementos. <section vl-scene vl-pin="6" vl-scrub>

PASSO 6

Navegador

Máscaras, timelines de rolagem e propriedades personalizadas. Nada para executar. animation-timeline: view();

12 / 17

EVIDÊNCIA MEASURED, NOT CLAIMED

Medido, não alegado.

Números com limites declarados.

PESO · MEDIDO

18,6 kB

motion-core em CSS, minificado + gzip. Sem script para interpretar e sem runtime para iniciar. GSAP + ScrollTrigger (44,6 kB) aparece só como escala.

EXECUÇÃO · MEDIDO

0 ms de script

para iniciar o movimento. Com CPU 4× mais lenta: +16% de trabalho da thread principal vs. +102% na versão guiada por script, no mesmo teste.

ACESSIBILIDADE · VALIDADO

AA em texto

Contraste calculado nos tokens do site, claro e escuro. Teclado percorrido em 11 páginas. Movimento reduzido e vl-motion="still" respeitados.

Limites: um cenário, uma máquina, Chromium 141, via localhost. Leitor de tela, modo de contraste forçado e celulares reais ainda não foram testados.

HELLO, VELORA ATTRIBUTE GRAMMAR

Uma cena inteira cabe em poucos atributos.

B2 / B7

CSS CONDICIONAL PROGRESSIVE ENHANCEMENT

Motion também pode responder ao contexto.

O modo muda.
O contrato permanece.

standardEquilíbrio entre tempo, distância e easing.
subtleRápido, curto, discreto.
cinematicMais profundidade, duração e presença.
stillMovimento reduzido por decisão autoral.

CSS if() é enhancement (Experimental). O baseline precisa continuar correto sem ele.

motion-conditions.css
/* baseline */
[vl-motion="subtle"] {
  --vl-distance: .55;
  --vl-duration: .8;
}

/* progressive enhancement */
@supports
  (width: if(media(width > 1px):
    1px; else: 2px)) {

  [vl-motion] {
    --vl-blur: if(
      media(prefers-reduced-motion: reduce):
      0;
      else: 12px
    );
  }
}

B5 / B7

O QUE O VELORA NÃO É BOUNDARIES MATTER

Limites claros tornam o projeto mais útil.

Não é “mais um Tailwind”.
Não é “GSAP sem JS”.

01

Não é um framework obrigatório de UI

Importe só motion-core e mantenha seu próprio sistema visual.

02

Não é uma timeline universal

Casos altamente programáticos continuam pertencendo a ferramentas programáticas.

03

Não elimina JavaScript do produto

A proposta é zero runtime JS para a lógica de animação — não “sites sem JavaScript” como dogma.

O objetivo é diminuir a superfície de JavaScript onde o browser já tem primitivas melhores.
